Voice Input — UI States

State 1: Idle — Mic Available

Mic button appears when input is empty. When text is present, it becomes a Send button.

State 2: Listening — Active Recording

Listening...

the project owner's office has 4 recessed ceiling lights on a dimmer...

Shows live interim transcription. Auto-submits after 2s of silence, or user taps "Done".

State 3: Processing — Sending to AI

🎤 Voice

the project owner's office has 4 recessed ceiling lights on a dimmer on the north wall, circuit 7

Ω
Ohm is thinking...

Final transcription shown as user message. Branded Ω orbs spinner while AI processes (replaces generic bouncing dots).

State 4: Text Entered — Send Button Replaces Mic

When text is present, mic → send button. Clears after submit → mic returns.

State 5: Voice Not Supported (Fallback)

If SpeechRecognition API unavailable, mic button hidden entirely. Text-only input with permanent send button.

Mobile Layout Considerations

📐

Mic button: 44×44px minimum tap target

Apple HIG minimum. We use 40px (10px rounded-full) which is close — bump to 44.

📱

Input bar sticks above keyboard

Use position: sticky; bottom: env(safe-area-inset-bottom) for iOS.

🔊

Haptic feedback on mic activation

navigator.vibrate(50) on tap — subtle confirmation that recording started.

🎤

Keep listening indicator above soft keyboard

Interim text and waveform must be visible even when virtual keyboard is open (relevant if user started via text then switches to voice).
